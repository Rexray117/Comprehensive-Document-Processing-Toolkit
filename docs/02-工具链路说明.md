# 02 · 工具链路说明

> 梳理「一次请求」从入口到产物走过的完整链路，以及四条集成路径的选择依据。

## 一、核心链路（所有路径殊途同归）

```
调用方请求                        {module, action, input, options}
    │
    ▼
core.dispatcher.run()            ← 唯一入口，永不抛异常
    │
    ├─ module=auto？──是──► core.utils.sniff() 三级类型判定
    │                       ① OOXML 容器标志文件（最可靠）
    │                       ② filetype 魔数
    │                       ③ 扩展名兜底
    │                      core.registry.module_for_kind() → 路由到 handler
    │
    ├─ 否──► registry.require_handler(module)
    │
    ▼
handlers/*_handler.py 的 @action 方法
    │  ActionContext 提供：get/flag/require（参数读取）
    │                     input_path()/info()（输入）
    │                     out_dir()/out_file()/emit()（产物登记）
    │
    ▼
统一信封 Response（所有模块同构，集成方零适配）
{
  "ok": true/false,  "module": "pdf",  "action": "read",
  "elapsed_ms": 18,  "warnings": [...],
  "artifacts": [{"path": "...", "kind": "markdown", "bytes": 1234}],
  "data": {...},     "error": null 或 {hint: "带 pip 修复命令"}
}
```

设计要点：**失败时 `error.hint` 直接携带修复命令**（如缺依赖时的 pip install 行），调用方可据此自愈；
`edit` 动作由 dispatch 层自动先备份（`<名称>_bak.<后缀>`）。

## 三、五个统一动作（跨 7 模块语义一致）

| 动作 | 语义 | 特性 |
| --- | --- | --- |
| `probe` | 极速探测 | 多数走 ZIP 层直读，不加载完整解析器 |
| `read` | 结构化读取 | 标题/段落/表格/公式/单元格/书签 |
| `analyze` | 内容识别 | 关键词、统计、质量诊断、**OCR**、扫描件判别 |
| `transform` | 转换导出 | 产出新文件到 `<名称>_out/`，`artifacts` 登记产物 |
| `edit` | 修改 | 默认就地保存 + 自动备份（pdf 模块只读，无 edit） |

运行时查询模块能力（给 Agent 用的自文档化接口）：

```bash
python -m core.cli cap pdf     # 返回该模块全部动作与参数说明（JSON）
python -m core.cli list        # 列出全部模块
```

## 四、跨模块协作链（组合用法）

1. **扫描件 PDF → 文字**：`pdf.analyze` 识别出 >50% 空文本页 → 提示走图像路径
   → `pdf.transform op=split` 拆页 → `image.analyze options.ocr=true` 逐页 OCR。
   设计原则：pdf 不内置 OCR 轮子，复用 image 的可插拔 OCR 链。
2. **DOCX 交付前的 OMML 公式**：`docx.transform` 导出/插入真 OMML（可编辑公式，非图片）。
3. **网页 → 单文件自包含 HTML**：`html.transform op=inline_assets` 把 CSS/JS/图片全部 base64 内联。
4. **批量目录处理**：`run_batch("./docs", "probe", kinds=["pptx","docx","xlsx"])`，按 kind 过滤、逐文件返回信封。

## 五、扩展新模块的固定流程（3 步 + 4 脚本）

1. 仿照 `handlers/txt_handler.py` 写一个 `BaseHandler` 子类（`module/extensions/kinds` + `@action`）；
2. 丢进 `skill/handlers/` —— registry 的 `pkgutil` 扫描自动发现，**框架零改动**；
3. 依次跑：
   ```bash
   scripts/doctor.py        # 依赖自检
   scripts/smoke_test.py    # 回归（当前 45 用例全过）
   scripts/gen_api_doc.py   # 重新生成 references/api-reference.md
   scripts/gen_tool_specs.py # 重新生成 bridges/tool_specs.json + harness 定义
   ```
4. 记得同步 `MANIFEST.json`、`CHANGELOG.md`、`SKILL.md` 模块表（v0.2 加 txt/pdf 时的完整清单见 `skill/CHANGELOG.md`）。
